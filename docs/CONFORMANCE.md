# Conformance

Conformance is layered so one kind of success cannot be mistaken for another.

## C0 — Structural

Required canonical files, schemas, scripts, and repository metadata exist and parse.

## C1 — Context

Compiled context regenerates deterministically from canonical source selection and its aggregate source digest matches current inputs.

## C2 — Bootstrap

A project can be instantiated from the release and passes local structural/context validation with project-specific intent/profile/resource state finalized.

## C3 — Operational

A project completes at least one reversible end-to-end work cycle through authorization, execution, candidate verification, evidence recording, disposition, and claim release.

## C4a — Directed cross-project conformance

The unmodified bootstrap succeeds in an unrelated project under an explicitly arranged qualification scenario.

This establishes that the environment can enact the specified behavior. It does **not** establish that the behavior would arise without evaluator steering.

## C4b — Behavioral transfer

The unmodified bootstrap succeeds in an unrelated project when the worker receives only the project objective and ordinary bootstrap entry instruction; target behaviors are not restated in the experiment prompt.

Evidence may include natural blocker handling, frontier reselection, landing separation, coordination, recovery, authority restraint, and honest unsupported-state reporting.

The project environment may of course contain its own canonical operating rules. The evaluator must not teach the tested response again in the worker prompt.

## C4c — Existing-project adoption

The unmodified bootstrap is adopted into a materially pre-existing project without replacing legitimate project authority, history, semantics, or operating boundaries.

PASS requires evidence that:

- pre-existing project identity and canonical authority were discovered before synthesis;
- conflicting bootstrap candidates were preserved rather than overwriting project files;
- bindings distinguish existing authority from bootstrap operating semantics;
- existing tests/gates continue to pass or any regression is explicitly attributed;
- unresolved contradictions remain represented;
- generated context is rebuilt from reconciled sources; and
- at least one bounded Ready item can execute after adoption without requiring the human to restate the migration procedure.

C4c does not establish comparative advantage or long-running autonomy.

## C5 — Comparative empirical evidence

Preregistered comparative runs test a claimed effect of the formal environment against a baseline condition, controlling model/task conditions where practical.

Examples include intervention count, premature stops, scope/authority violations, unsupported claims, recovery success, repeated failed approaches, evidence quality, context cost, and model capability required.

A release must state the highest level actually established and the experimental condition used.
